## Overview

The shadcn/ui registry is a **distribution system for code**. Run your own code
registry with the `shadcn` CLI to distribute custom components, hooks, pages,
config, rules, and other files to any project. It works with any project type
and any framework -- not limited to React.

A registry can be hosted three ways:

- A web app that serves JSON over HTTP (Next.js, Vite, Vue, Svelte, PHP, etc.).
- A **public GitHub repository** with a `registry.json` at its root (no server,
  no build/publish step -- see [GitHub Registries](#github-registries)).
- Static JSON files generated by `shadcn build`, served from any host.

Docs sidebar order (for orientation): Introduction, Getting Started, GitHub
Registries, Registry Directory, Examples, Namespaces, Authentication, MCP
Server, Open in v0, API Reference, `registry.json`, `registry-item.json`.

## Registry Structure

### registry.json (Source of Truth)

The `registry.json` file is the foundational configuration. It sits at the
registry's root endpoint and contains metadata plus the inventory of available
items (or `include` references to other `registry.json` files). It is required
to run your own registry.

**Schema**: `https://ui.shadcn.com/schema/registry.json`

```json
{
  "$schema": "https://ui.shadcn.com/schema/registry.json",
  "name": "acme",
  "homepage": "https://acme.com",
  "items": []
}
```

#### Properties

| Property | Type | Required | Description |
|----------|------|----------|-------------|
| `$schema` | string | yes | Schema URL: `"https://ui.shadcn.com/schema/registry.json"` |
| `name` | string | root only | Registry name (data attributes / metadata). Required on the root file; optional in included chunks. |
| `homepage` | string | root only | Registry homepage URL. Required on the root file; optional in included chunks. |
| `include` | string[] | no | Relative paths to other `registry.json` files to compose into this registry (alternative to `items`). |
| `items` | array | no (default `[]`) | Registry items, each conforming to the registry-item schema. |

> The root `registry.json` must define **at least one** of `items` or `include`
> (schema constraint `anyOf: [{required:[items]}, {required:[include]}]`).

### registry-item.json (Individual Items)

**Schema**: `https://ui.shadcn.com/schema/registry-item.json`

Each registry item is a JSON file conforming to this spec. Items define the
type, files, dependencies, styling, and target paths for installation.

## Registry Item Schema - Complete Field Reference

### Core Properties

| Property | Type | Required | Description |
|----------|------|----------|-------------|
| `$schema` | string | no | `"https://ui.shadcn.com/schema/registry-item.json"` |
| `name` | string | yes | Unique identifier within registry (e.g. `"hello-world"`) |
| `title` | string | yes | Human-readable concise title |
| `description` | string | yes | What the item does or provides |
| `type` | string | yes | Item classification (see types below) |
| `author` | string | no | Creator info. Format: `"Name <email@domain.com>"` |
| `extends` | string | no | Set to `"none"` to create a style/base from scratch (no shadcn/ui defaults) |

### Item Types

| Type | Purpose |
|------|---------|
| `registry:base` | Entire design systems (uses a `config` block) |
| `registry:block` | Complex components with multiple files (page + components) |
| `registry:component` | Simple standalone components |
| `registry:font` | Fonts (uses a `font` object) |
| `registry:lib` | Lib and utils |
| `registry:hook` | Hooks / composables |
| `registry:ui` | UI components and single-file primitives |
| `registry:page` | Page or file-based routes (requires `target`) |
| `registry:file` | Miscellaneous files (requires `target`) |
| `registry:style` | Registry styles (e.g. `new-york`) |
| `registry:theme` | Themes (color/spacing variables) |
| `registry:item` | Universal / framework-agnostic items |

### Dependency Properties

| Property | Type | Description |
|----------|------|-------------|
| `dependencies` | string[] | NPM runtime packages. Format: `"package-name"` or `"package-name@version"` |
| `devDependencies` | string[] | NPM dev-only packages. Same format. |
| `registryDependencies` | string[] | Other registry items. See address forms below. |

`registryDependencies` address forms (each entry is an item address):

- **Bare name** -- `"button"` (resolves to the built-in shadcn item, **not** a
  same-repo GitHub item).
- **Namespaced** -- `"@acme/input-form"`.
- **GitHub** -- `"acme/ui/button"` or pinned `"acme/ui/button#v1.2.0"`
  (`owner/repo/item[#ref]`; prefer a tag or full commit SHA).
- **Custom URL** -- `"https://example.com/r/hello-world.json"`.
- **Local file** -- `"./hello-world.json"`.

### Files Property

Each file object:

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `path` | string | yes | Source location. Single-file registry: relative to project root. With `include`: relative to the declaring `registry.json`. |
| `type` | string | yes | File classification (same values as item types) |
| `target` | string | conditional | Installation destination. **Required** for `registry:page` and `registry:file`. `target` controls the write location even when it differs from the file `type`. |
| `content` | string | varies | File content (included in built output, excluded from registry-index submissions) |

**Target placeholders** (resolved from `components.json` aliases, so an item
works across `@/`, custom TS aliases, package imports, and workspace exports):

| Placeholder | Resolves to |
|-------------|-------------|
| `@components/` | `aliases.components` |
| `@ui/` | `aliases.ui` |
| `@lib/` | `aliases.lib` |
| `@hooks/` | `aliases.hooks` |
| `~/` | project root (e.g. `~/.env`, `~/AGENTS.md`) |

Anything after a placeholder is preserved -- `@ui/ai/prompt-input.tsx` installs
under the configured `ui` directory at `ai/prompt-input.tsx`.

### Styling Properties

#### `cssVars` (object, optional)

CSS variable definitions by scope:

```json
{
  "theme": { "font-heading": "Poppins, sans-serif" },
  "light": { "brand": "oklch(0.205 0.015 18)" },
  "dark": { "brand": "oklch(0.205 0.015 18)" }
}
```

- `theme` -- variables applied regardless of mode (fonts, spacing, animations).
  Add or override Tailwind theme variables here (e.g. `text-base`,
  `font-heading`). Required half of any custom animation (`--animate-*`).
- `light` -- light mode variables (colors, etc.). Exposed as utility classes
  (e.g. a `brand` var becomes `bg-brand`).
- `dark` -- dark mode variables.

#### `css` (object, optional)

CSS rules using Tailwind v4 directives:

```json
{
  "@import \"tw-animate-css\"": {},
  "@plugin \"@tailwindcss/typography\"": {},
  "@layer base": {
    "body": { "@apply bg-background text-foreground": {} }
  },
  "@layer components": {
    ".card": { "border-radius": "var(--rounded-lg)" }
  },
  "@utility content-auto": {
    "content-visibility": "auto"
  },
  "@keyframes wiggle": {
    "0%, 100%": { "transform": "rotate(-3deg)" },
    "50%": { "transform": "rotate(3deg)" }
  }
}
```

Supports: `@import`, `@plugin`, `@layer base`, `@layer components`, `@utility`,
`@keyframes`. Ordering: `@import` first, then `@plugin`, then other CSS.
`@plugin` packages from npm must **also** appear in `dependencies`; multiple
plugins are grouped and deduplicated automatically.

#### `tailwind` (object, optional -- DEPRECATED)

Legacy Tailwind config. Use `cssVars.theme` for Tailwind v4 instead.

### Environment & Documentation

| Property | Type | Description |
|----------|------|-------------|
| `envVars` | object | Key-value environment variables written to `.env.local` or `.env`. Existing vars are not overwritten. Use for dev/example values only, never production. |
| `docs` | string | Custom docs/instructions shown by the CLI at install time |
| `categories` | string[] | Tags for organizing (e.g. `["sidebar", "dashboard"]`) |
| `meta` | object | Arbitrary key-value metadata |

### Font Property (required for `registry:font`)

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `family` | string | yes | Font family declaration (e.g. `"'Inter Variable', sans-serif"`) |
| `provider` | string | yes | Currently only `"google"` |
| `import` | string | yes | Import name (e.g. `"Inter"`, `"JetBrains_Mono"`) |
| `variable` | string | yes | CSS variable name (e.g. `"--font-sans"`) |
| `subsets` | string[] | yes | Font subsets (e.g. `["latin"]`) |
| `weight` | string[] | no | Font weights (e.g. `["400", "500", "600"]`) |
| `selector` | string | no | CSS selector to apply the font to instead of `<html>` (e.g. `"h1, h2, h3"`). The variable is still injected on `<html>`. |
| `dependency` | string | yes | NPM package for the font (e.g. `"@fontsource-variable/inter"`) |

### Config Property (used with `registry:base`)

All properties optional. Defaults: `rsc=false`, `tsx=true`, `rtl=false`,
`menuColor="default"`, `menuAccent="subtle"`.

| Field | Type | Description |
|-------|------|-------------|
| `style` | string | Style name |
| `iconLibrary` | string | Icon library (e.g. `"lucide"`) |
| `rsc` | boolean | React Server Components support (default `false`) |
| `tsx` | boolean | TypeScript JSX support (default `true`) |
| `rtl` | boolean | RTL enablement (default `false`) |
| `menuColor` | enum | `"default" \| "inverted" \| "default-translucent" \| "inverted-translucent"` (default `"default"`) |
| `menuAccent` | enum | `"subtle" \| "bold"` (default `"subtle"`) |
| `tailwind.baseColor` | string | Base color (e.g. `"neutral"`, `"slate"`, `"zinc"`) |
| `tailwind.css` | string | Path to the Tailwind CSS file |
| `tailwind.prefix` | string | Prefix added to all Tailwind classes |
| `aliases.components` / `.utils` / `.ui` / `.lib` / `.hooks` | string | Import aliases |
| `registries` | `Record<string, string \| object>` | Custom registry URLs; keys must start with `@` |

## Getting Started

### 1. Requirements

The registry catalog and items must conform to the `registry.json` and
`registry-item.json` schemas. The registry can be any framework that serves JSON
over HTTP, or a public GitHub repo with a root `registry.json`. A template
project is available as a starting point.

### 2. Structure Your Registry

**Option A: single `registry.json`** -- define every item in the root `items`
array.

**Option B: `include`** -- a root `registry.json` composes multiple nested
`registry.json` files:

```json
{
  "$schema": "https://ui.shadcn.com/schema/registry.json",
  "name": "acme",
  "homepage": "https://acme.com",
  "include": ["components/ui/registry.json", "hooks/registry.json"]
}
```

`include` rules:

- Each path must point at an explicit `registry.json` file (no folder
  shorthand).
- Included files may omit `name` and `homepage`.
- File paths in an included file are relative to that file.
- Item names must be unique across the resolved registry.
- `shadcn build` flattens includes; the generated `registry.json` has no
  `include`.

### 3. Add an Item

Add an item definition with `name`, `type`, `title`, `description`, and `files`;
each file needs a `path` and `type`:

```json
{
  "$schema": "https://ui.shadcn.com/schema/registry.json",
  "name": "acme",
  "homepage": "https://acme.com",
  "items": [
    {
      "name": "button",
      "type": "registry:ui",
      "title": "Button",
      "description": "A simple button component.",
      "files": [
        { "path": "components/ui/button.tsx", "type": "registry:ui" }
      ]
    }
  ]
}
```

### 4. Serve Your Registry

**Option A -- static JSON** (`shadcn build`):

```bash
pnpm dlx shadcn@latest build
```

Output defaults to `public/r/` (one JSON per item, e.g. `public/r/button.json`).
Change with `--output`. Includes are resolved and flattened. Served at
`http://localhost:3000/r/[NAME].json` when running the dev server.

**Option B -- dynamic route handlers** (serve from source at request time using
the `shadcn/registry` runtime; install `shadcn` as a dependency):

```ts
// app/r/registry.json/route.ts
import { loadRegistry } from "shadcn/registry"

export async function GET() {
  try {
    const registry = await loadRegistry()

    return Response.json(registry)
  } catch (error) {
    console.error(error)

    return Response.json({ error: "Failed to load registry." }, { status: 500 })
  }
}
```

```ts
// app/r/[name].json/route.ts
import { loadRegistryItem, RegistryItemNotFoundError } from "shadcn/registry"

export async function GET(
  _request: Request,
  context: { params: Promise<{ name: string }> }
) {
  const { name } = await context.params

  try {
    const item = await loadRegistryItem(name)

    return Response.json(item)
  } catch (error) {
    if (error instanceof RegistryItemNotFoundError) {
      return Response.json(
        { error: `Registry item "${name}" was not found.` },
        { status: 404 }
      )
    }

    console.error(error)

    return Response.json(
      { error: "Failed to load registry item." },
      { status: 500 }
    )
  }
}
```

Both loaders resolve `include` before returning JSON, so route handlers reuse
the source `registry.json` without running `shadcn build`.

### 5. Test Your Registry

Use the **catalog URL** for discovery (`list`, `search`) and **item URLs** for
read/install (`view`, `add`). Works with a URL or a namespace:

```bash
# via URL
pnpm dlx shadcn@latest list   http://localhost:3000/r/registry.json
pnpm dlx shadcn@latest search http://localhost:3000/r/registry.json --query button
pnpm dlx shadcn@latest view   http://localhost:3000/r/button.json
pnpm dlx shadcn@latest add    http://localhost:3000/r/button.json

# via namespace (register, then use @acme/<item>)
pnpm dlx shadcn@latest registry add @acme=http://localhost:3000/r/{name}.json
pnpm dlx shadcn@latest add @acme/button
```

### Guidelines

- Place items in `registry/[STYLE]/[NAME]` (e.g. style `default`).
- For blocks, `name`, `description`, `type`, and `files` are required.
- Add a descriptive `name` and `description` (helps LLM/MCP comprehension).
- List all `registryDependencies` and `dependencies` explicitly.
- Imports should use the `@/registry` path.
- Place files within `components`, `hooks`, or `lib` subdirectories.

## GitHub Registries

Turn any **public** `github.com` repository into a registry by adding a
`registry.json` at the repo root. The repo itself is the source registry -- no
separate server, no build/publish step.

```bash
pnpm dlx shadcn@latest add <username>/<repo>/<item>
```

### Requirements

- Public `github.com` repository (private repos and GitHub Enterprise are **not
  supported** -- use a namespace with authentication instead).
- `registry.json` at the repository root.
- Valid `registry.json` / `registry-item.json` schemas.
- Source files that actually exist in the repo.

### What you can distribute

Components, helpers/utilities, design-system packages, feature kits, agent
workflows (`.cursor/rules/*`, `.claude/commands/*`), project conventions
(`.editorconfig`, `biome.json`), codemods, testing setup, CI/release workflows,
automation scripts, issue/PR templates, MCP configuration -- using
`registry:item` / `registry:file` with a `target`.

```json
{
  "$schema": "https://ui.shadcn.com/schema/registry.json",
  "name": "acme-toolkit",
  "homepage": "https://github.com/acme/toolkit",
  "items": [
    {
      "name": "project-conventions",
      "type": "registry:item",
      "title": "Project Conventions",
      "description": "Shared project conventions, editor settings and agent instructions.",
      "files": [
        { "path": "AGENTS.md", "type": "registry:file", "target": "~/AGENTS.md" },
        { "path": ".editorconfig", "type": "registry:file", "target": "~/.editorconfig" },
        { "path": "docs/conventions.md", "type": "registry:file", "target": "~/docs/conventions.md" }
      ]
    }
  ]
}
```

### Address format

The first two path segments are the GitHub **owner** and **repo**; everything
after is the **item name** (not a file path), so it may contain slashes:

```bash
pnpm dlx shadcn@latest add acme/toolkit/project-conventions
pnpm dlx shadcn@latest add acme/toolkit/rules/agent   # item name is "rules/agent"
```

An address ending in `.json` is treated as a file path, not an item name.

### Refs (branches, tags, commit SHAs)

Pin with a `#ref` suffix on the address (or in `registryDependencies`):

```bash
pnpm dlx shadcn@latest add acme/toolkit/project-conventions#main
pnpm dlx shadcn@latest add acme/toolkit/project-conventions#feature/conventions
pnpm dlx shadcn@latest add acme/toolkit/project-conventions#v1.0.0
pnpm dlx shadcn@latest add acme/toolkit/project-conventions#c0ffee254729296a45d6691db565cf707a3fef5d
```

- No ref -> the repository default branch.
- The CLI uses Git to resolve branches/tags/short refs into a commit SHA before
  reading files; full 40-character SHAs are used directly (most reproducible).

### Registry dependencies in GitHub registries

- Same-repo: `"acme/toolkit/agent-rules"`
- External GitHub: `"contoso/devtools/prettier-config"`
- Namespaced: `"@acme/tsconfig"`
- Each can be pinned with `#ref` (tag or full SHA).
- Bare names (e.g. `"button"`) still mean the built-in shadcn item, **not** a
  same-repo item.

### Validate, list, search, view

```bash
pnpm dlx shadcn@latest registry validate acme/toolkit
pnpm dlx shadcn@latest registry validate acme/toolkit#v1.0.0
pnpm dlx shadcn@latest list   acme/toolkit
pnpm dlx shadcn@latest search acme/toolkit --query conventions
pnpm dlx shadcn@latest view   acme/toolkit/project-conventions
```

### Review before installing

GitHub items install third-party code. Review the repo and root `registry.json`,
and the item's `files`, `target`, `dependencies`, `devDependencies`,
`registryDependencies`, and `envVars`. Prefer pinned refs (full SHA). Preview
with `--dry-run`, inspect with `--diff` / `--view`, or `shadcn view`.

## Namespaces

Namespaces use the `@` prefix to organize resources from different registries:
`@shadcn/button`, `@v0/dashboard`, `@acme/auth-utils`. The system is
decentralized -- no central authority approval needed (there is an optional
open-source [Registry Directory](#registry-directory-open-source-listing)).

### GitHub addresses vs namespaces

- Use a **GitHub address** (`acme/ui/button`) when the registry is a public
  GitHub repo and users should install without configuring `components.json`.
- Use a **namespace** (`@acme/button`) when you want a stable alias, custom
  hosting, authentication, headers, query params, or private-registry support.

### Configuration in components.json

Configured under the `registries` field. A value is either a URL template string
or an object with `url`, `headers`, and `params`.

#### Basic

```json
{
  "registries": {
    "@v0": "https://v0.dev/chat/b/{name}",
    "@acme": "https://registry.acme.com/resources/{name}.json"
  }
}
```

`@acme/button` becomes `https://registry.acme.com/resources/button.json`.

#### With Authentication

```json
{
  "registries": {
    "@private": {
      "url": "https://api.company.com/registry/{name}.json",
      "headers": {
        "Authorization": "Bearer ${REGISTRY_TOKEN}",
        "X-API-Key": "${API_KEY}"
      },
      "params": {
        "version": "latest"
      }
    }
  }
}
```

`${VAR_NAME}` is auto-expanded from `process.env` in URLs, headers, and params.
Add a namespace via CLI: `shadcn registry add @acme=https://acme.com/r/{name}.json`.

### URL Placeholders

| Placeholder | Description |
|-------------|-------------|
| `{name}` | Required. Replaced with the resource name |
| `{style}` | Optional. Replaced with the configured style (e.g. `new-york`) |

### Naming Convention

- Must start with `@`; alphanumeric, hyphens, underscores only.
- Pattern: `@namespace/resource-name`.
- Regex: `/^(@[a-zA-Z0-9](?:[a-zA-Z0-9-_]*[a-zA-Z0-9])?)\/(.+)$/`

### Versioning (via query params)

```json
{
  "@versioned": {
    "url": "https://registry.example.com/{name}",
    "params": { "version": "v2" }
  },
  "@npm-style": {
    "url": "https://registry.example.com/{name}",
    "params": { "semver": "^2.0.0", "prerelease": "${ALLOW_PRERELEASE}" }
  }
}
```

Use env vars for version control across environments; the `${VAR:-default}`
default syntax is supported. Support version pinning for reproducible builds and
cache versioned resources with proper headers.

### CLI Usage

```bash
pnpm dlx shadcn@latest add @v0/dashboard
pnpm dlx shadcn@latest add @acme/header @lib/auth-utils
pnpm dlx shadcn@latest search @v0 --query "auth"
pnpm dlx shadcn@latest search @v0 --limit 10 --offset 20
pnpm dlx shadcn@latest view @acme/button
pnpm dlx shadcn@latest list @acme           # list is an alias for search
```

## Dependency Resolution

### Cross-Registry Dependencies

Items can depend on resources from different registries:

```json
{
  "name": "dashboard",
  "type": "registry:block",
  "registryDependencies": ["@shadcn/card", "@v0/chart", "@acme/data-table"]
}
```

### Resolution Process

When running `shadcn add @namespace/resource`:

1. Clears registry context.
2. Fetches the main resource from the specified registry.
3. Recursively resolves dependencies from their respective registries.
4. Applies topological sorting for proper install order.
5. Deduplicates files based on target paths (**last wins**).
6. Deep merges configurations (`tailwind`, `cssVars`, `css`, `envVars`).

### Override Pattern

Install a base item, then override specific files. The later dependency's file
wins:

```json
{
  "name": "custom-auth",
  "registryDependencies": ["@vendor/auth"],
  "files": [
    {
      "path": "lib/auth-server.ts",
      "type": "registry:lib",
      "content": "// Your custom auth server"
    }
  ]
}
```

You can also override only `cssVars` (e.g. re-skin a vendor button) or extend
without replacing (add a new file alongside the original).

### Key Features

- Separate auth contexts per registry.
- Circular dependency detection.
- Smart installation ordering (deps first).
- File deduplication by target path.

## Authentication

Authentication enables private components, team-specific resources, access
control, usage analytics, and licensing. Configure client-side under
`registries` (see [Namespaces](#with-authentication)); implement validation
server-side.

### Client Configuration

```json
{
  "registries": {
    "@private": {
      "url": "https://registry.company.com/{name}.json",
      "headers": { "Authorization": "Bearer ${REGISTRY_TOKEN}" }
    }
  }
}
```

Supported patterns: Bearer token, API key header (`X-API-Key`), basic auth,
query-parameter token, and combinations. Set secrets in `.env.local`
(`REGISTRY_TOKEN=...`).

### Server-Side Patterns

- Validate the token from the `Authorization` header or `?token=` query param.
- Return `401`/`403`/`429` as appropriate.
- Advanced: team-based access, user-personalized registries, temporary
  (expiring) tokens, rate limiting, token rotation.

### Custom Error Messages

The server can return a `message` that the CLI surfaces to the user:

```ts
return NextResponse.json(
  {
    error: "Unauthorized",
    message: "Your subscription has expired. Renew at company.com/billing",
  },
  { status: 403 }
)
```

### Security Best Practices

1. Store credentials in env vars, never in version control.
2. Always use HTTPS for registry URLs.
3. Implement rate limiting server-side.
4. Rotate tokens regularly (e.g. 30-day rotation).
5. Maintain access logs for security audits.

Environment variables are never logged, expanded at runtime only, and isolated
per registry. Resources are validated against the item schema (data, not
executable code) and written only to configured paths.

### Error Codes

| Code | Meaning |
|------|---------|
| 401 | Invalid or missing credentials |
| 403 | Insufficient permissions |
| 404 | Resource not found |
| 429 | Rate limit exceeded |

## MCP Server Integration

The shadcn MCP server works out of the box with any shadcn-compatible registry,
letting AI assistants (Claude Code, Cursor, VS Code, Codex) browse and install
items.

### Prerequisite

Host a registry **index** file at the registry root named `registry` or
`registry.json` (valid JSON conforming to the registry schema). For a registry
at `https://acme.com/r/[name].json`, also serve
`https://acme.com/r/registry.json`.

### Setup for Consumers

1. Configure the registry in `components.json`:

```json
{
  "registries": { "@acme": "https://acme.com/r/{name}.json" }
}
```

2. Initialize the MCP server (`--client` accepts `claude`, `cursor`, `vscode`,
   `codex`, `code`):

```bash
pnpm dlx shadcn@latest mcp init --client claude
```

3. Restart the client and prompt, e.g. "Show me the components in the acme
   registry". Use `/mcp` in Claude Code to debug.

### Best Practices for MCP Compatibility

1. Add concise, informative `description` fields.
2. List all `dependencies` accurately for automatic installation.
3. Use `registryDependencies` to indicate item relationships.
4. Use kebab-case naming consistently.

## Registry Directory (Open Source Listing)

The shadcn/ui platform maintains an open-source registry **directory** (URL slug
`registry-index`). When developers run `shadcn add` or `shadcn search`, the CLI
auto-checks the directory and adds matching registries to `components.json`.

### Submission Requirements

- Registry must be **open source and publicly accessible**.
- Must be a **valid JSON file** conforming to the registry schema.
- Must be a **flat registry** (no nested items) -- `/registry.json` and
  `/component-name.json` at the root.
- The `files` array must **NOT include a `content` property**.

### Steps

1. Add the registry to `apps/v4/registry/directory.json` in the shadcn/ui repo.
2. Run `pnpm validate:registries`.
3. Open a pull request to `github.com/shadcn-ui/ui`.

Full machine-readable list: `https://ui.shadcn.com/r/registries.json`

## Open in v0

If the registry is hosted and publicly accessible, open an item in v0 via:

```
https://v0.dev/chat/api/open?url=[URL]
```

Example: `https://v0.dev/chat/api/open?url=https://ui.shadcn.com/r/styles/new-york/login-01.json`

### Button component

```tsx
import { Button } from "@/components/ui/button"

export function OpenInV0Button({ url }: { url: string }) {
  return (
    <Button
      aria-label="Open in v0"
      className="h-8 gap-1 rounded-[6px] bg-black px-3 text-xs text-white hover:bg-black hover:text-white dark:bg-white dark:text-black"
      asChild
    >
      <a href={`https://v0.dev/chat/api/open?url=${url}`} target="_blank" rel="noreferrer">
        Open in v0
      </a>
    </Button>
  )
}
```

### Authentication and limitations

- Only **query-parameter** token auth is supported (`?token=...`). Header-based
  auth (Bearer / API key) is not. Return `401` for invalid/missing tokens; both
  the CLI and Open in v0 surface the message.
- **Not supported**: `cssVars`, `css`, `envVars`, namespaced registries, and
  advanced authentication methods.
- Encrypt and expire tokens; never expose production tokens in docs/examples.

## API Reference (Programmatic)

The `shadcn` package exposes programmatic APIs via subpath imports.

```ts
import { getRegistryItems } from "shadcn/registry"
import { registryItemSchema } from "shadcn/schema"
import { encodePreset } from "shadcn/preset"
```

### `shadcn/registry`

Common options: `config` (`Partial<Config>`, maps namespaces to URLs with
auth headers/env vars from `components.json`) and `useCache`
(`boolean`, default `true`; set `false` in long-running servers/watchers).

| Function | Purpose |
|----------|---------|
| `getRegistry(name, options)` | Fetch a single registry by namespace name |
| `getRegistryItems(names[], options)` | Fetch items by qualified names (returns name, type, dependencies, files) |
| `resolveRegistryItems(names[], options)` | Walk `registryDependencies` and flatten files/deps/CSS vars into one installable object |
| `getRegistries(options)` | Fetch the registry directory (name, url, homepage) |
| `searchRegistries(names[], options)` | Fuzzy search (query, types, limit, offset, continueOnError) with pagination metadata |
| `loadRegistry(options)` | Read local `registry.json` from disk, resolving `include` (accepts `cwd`, `registryFile`) |
| `loadRegistryItem(name, options)` | Build a single item on demand from local source files |

Error classes: `RegistryError`, `RegistryNotFoundError`,
`RegistryUnauthorizedError`, `RegistryForbiddenError`, `RegistryFetchError`,
`RegistryNotConfiguredError`, `RegistryLocalFileError`, `RegistryParseError`,
`RegistryValidationError`, `RegistryItemNotFoundError`,
`RegistriesIndexParseError`, `RegistryMissingEnvironmentVariablesError`,
`RegistryInvalidNamespaceError`.

### `shadcn/schema`

Zod schemas: `registrySchema`, `registryItemSchema`, `registryItemFileSchema`,
`registryItemTypeSchema`, `registryItemCssVarsSchema`,
`registryItemTailwindSchema`, `registryBaseColorSchema`, `configSchema`,
`presetSchema`. Inferred types: `Registry`, `RegistryItem`,
`RegistryBaseItem`, `RegistryFontItem`, `Preset`, `ConfigJson`.

### `shadcn/preset`

`encodePreset(config)`, `decodePreset(code)`, `isPresetCode`, `isValidPreset`,
`generateRandomConfig`, `generateRandomPreset`, `toBase62`, `fromBase62`, plus
`PRESET_*` constants and `DEFAULT_PRESET_CONFIG`.

## Item Type Examples

### registry:ui (UI Component)

```json
{
  "$schema": "https://ui.shadcn.com/schema/registry-item.json",
  "name": "button",
  "type": "registry:ui",
  "dependencies": ["radix-ui"],
  "files": [
    { "path": "ui/button.tsx", "content": "...", "type": "registry:ui" }
  ]
}
```

### registry:block (Multi-File Block)

```json
{
  "$schema": "https://ui.shadcn.com/schema/registry-item.json",
  "name": "login-01",
  "type": "registry:block",
  "description": "A simple login form.",
  "registryDependencies": ["button", "card", "input", "label"],
  "files": [
    {
      "path": "blocks/login-01/page.tsx",
      "content": "...",
      "type": "registry:page",
      "target": "app/login/page.tsx"
    },
    {
      "path": "blocks/login-01/components/login-form.tsx",
      "content": "...",
      "type": "registry:component"
    }
  ]
}
```

### registry:lib (Utility)

```json
{
  "$schema": "https://ui.shadcn.com/schema/registry-item.json",
  "name": "utils",
  "type": "registry:lib",
  "dependencies": ["clsx", "tailwind-merge"],
  "files": [
    {
      "path": "lib/utils.ts",
      "content": "import { clsx, type ClassValue } from \"clsx\"\nimport { twMerge } from \"tailwind-merge\"\n\nexport function cn(...inputs: ClassValue[]) {\n  return twMerge(clsx(inputs))\n}",
      "type": "registry:lib"
    }
  ]
}
```

### registry:hook (Composable)

```json
{
  "$schema": "https://ui.shadcn.com/schema/registry-item.json",
  "name": "use-mobile",
  "type": "registry:hook",
  "files": [
    { "path": "hooks/use-mobile.ts", "content": "...", "type": "registry:hook" }
  ]
}
```

### registry:style (Custom Style)

```json
{
  "$schema": "https://ui.shadcn.com/schema/registry-item.json",
  "name": "example-style",
  "type": "registry:style",
  "dependencies": ["@tabler/icons-react"],
  "registryDependencies": ["login-01", "calendar"],
  "cssVars": {
    "theme": { "font-sans": "Inter, sans-serif" },
    "light": { "brand": "20 14.3% 4.1%" },
    "dark": { "brand": "20 14.3% 4.1%" }
  }
}
```

Use `"extends": "none"` to create a style from scratch (no shadcn/ui defaults).

### registry:theme

```json
{
  "$schema": "https://ui.shadcn.com/schema/registry-item.json",
  "name": "custom-theme",
  "type": "registry:theme",
  "cssVars": {
    "light": {
      "background": "oklch(1 0 0)",
      "primary": "oklch(0.546 0.245 262.881)",
      "primary-foreground": "oklch(0.97 0.014 254.604)"
    },
    "dark": {
      "background": "oklch(0.141 0.005 285.823)",
      "primary": "oklch(0.707 0.165 254.624)",
      "primary-foreground": "oklch(0.97 0.014 254.604)"
    }
  }
}
```

### registry:font

```json
{
  "$schema": "https://ui.shadcn.com/schema/registry-item.json",
  "name": "font-inter",
  "type": "registry:font",
  "font": {
    "family": "'Inter Variable', sans-serif",
    "provider": "google",
    "import": "Inter",
    "variable": "--font-sans",
    "subsets": ["latin"],
    "dependency": "@fontsource-variable/inter"
  }
}
```

Add `selector` (e.g. `"h1, h2, h3, h4, h5, h6"`) to apply a heading font to
specific selectors via `@apply` instead of `<html>`.

### registry:base

```json
{
  "$schema": "https://ui.shadcn.com/schema/registry-item.json",
  "name": "custom-base",
  "type": "registry:base",
  "config": {
    "style": "custom-base",
    "iconLibrary": "lucide",
    "tailwind": { "baseColor": "neutral" }
  },
  "dependencies": ["class-variance-authority", "tw-animate-css", "lucide-react"],
  "registryDependencies": ["utils", "font-inter"],
  "cssVars": {
    "light": {
      "background": "oklch(1 0 0)",
      "foreground": "oklch(0.141 0.005 285.823)"
    },
    "dark": {
      "background": "oklch(0.141 0.005 285.823)",
      "foreground": "oklch(0.985 0 0)"
    }
  },
  "css": {
    "@import \"tw-animate-css\"": {},
    "@layer base": {
      "*": { "@apply border-border outline-ring/50": {} },
      "body": { "@apply bg-background text-foreground": {} }
    }
  }
}
```

### Universal Items (registry:item)

Since `v2.9.0`, universal items install without framework detection or
`components.json` -- **every** file must have an explicit `target` (use the
`~/` prefix). For arbitrary files (Cursor rules, ESLint configs, starters):

```json
{
  "$schema": "https://ui.shadcn.com/schema/registry-item.json",
  "name": "python-rules",
  "type": "registry:item",
  "files": [
    {
      "path": "/path/to/custom-python.mdc",
      "type": "registry:file",
      "target": "~/.cursor/rules/custom-python.mdc",
      "content": "..."
    }
  ]
}
```

## CSS Patterns Reference

### Custom Animations

Define **both** the `@keyframes` (in `css`) and the matching `theme` variable
(in `cssVars`):

```json
{
  "cssVars": { "theme": { "--animate-wiggle": "wiggle 1s ease-in-out infinite" } },
  "css": {
    "@keyframes wiggle": {
      "0%, 100%": { "transform": "rotate(-3deg)" },
      "50%": { "transform": "rotate(3deg)" }
    }
  }
}
```

### Override Tailwind Variables

```json
{
  "cssVars": {
    "theme": { "spacing": "0.2rem", "breakpoint-sm": "640px", "breakpoint-md": "768px" }
  }
}
```

### Import + Plugin + Layer + Utility

`@import` first, then `@plugin` (npm plugins must also be in `dependencies`),
then other CSS:

```json
{
  "dependencies": ["@tailwindcss/typography"],
  "css": {
    "@import \"tailwindcss\"": {},
    "@plugin \"@tailwindcss/typography\"": {},
    "@layer base": { "body": { "font-family": "Inter, sans-serif" } },
    "@utility content-auto": { "content-visibility": "auto" }
  }
}
```

## FAQ Highlights

- **Complex component** -- a single `registry:block` item can bundle
  `registry:page` (with `target`), `registry:component`, `registry:hook`,
  `registry:lib`, and `registry:file` (with `target`) files.
- **Add a Tailwind color** -- add it under `cssVars.light` and `cssVars.dark`;
  it becomes a utility class (e.g. `bg-brand`).
- **Add/override a theme variable** -- add it under `cssVars.theme`.
- **GitHub deps** -- a bare `"button"` in `registryDependencies` always means
  the built-in shadcn item; use the full `owner/repo/item` form for a repo item.
- **Pin a GitHub item** -- append `#ref` (branch, tag, or full SHA); prefer
  tags/SHAs for published registries.
- **Private repos** -- not supported via GitHub addresses; use a namespace with
  authenticated URLs.

## Error Handling Reference

| Scenario | Error Message Pattern |
|----------|-----------------------|
| Unknown registry | `Unknown registry "@name". Make sure it is defined in components.json` |
| Missing env var | `Registry "@name" requires the following environment variables: - VAR_NAME` |
| 404 Not Found | `The item at [URL] was not found. It may not exist at the registry.` |
| 401 Unauthorized | `You are not authorized to access the item at [URL]` |
| 403 Forbidden | `Access forbidden for [URL]. Verify your API key has the necessary permissions.` |
| 429 Too Many Requests | Rate limit exceeded |

## CLI Commands Reference

```bash
# Build static registry JSON (default output public/r; --output to change)
pnpm dlx shadcn@latest build
pnpm dlx shadcn@latest build --output ./dist/r

# Add: from URL, namespace, GitHub address (optional #ref), or local file
pnpm dlx shadcn@latest add https://registry.example.com/button.json
pnpm dlx shadcn@latest add @acme/button
pnpm dlx shadcn@latest add acme/toolkit/project-conventions#v1.0.0
pnpm dlx shadcn@latest add ./local-registry/button.json

# Preview/inspect before applying
pnpm dlx shadcn@latest add @acme/button --dry-run
pnpm dlx shadcn@latest add @acme/button --diff
pnpm dlx shadcn@latest add @acme/button --view

# Inspect an item's resolved payload
pnpm dlx shadcn@latest view @acme/button

# Search / list (list is an alias for search)
pnpm dlx shadcn@latest search @v0 --query "auth" --limit 10 --offset 20
pnpm dlx shadcn@latest list @acme

# Register a namespace into components.json
pnpm dlx shadcn@latest registry add @acme=https://acme.com/r/{name}.json

# Validate a registry (works with GitHub addresses + #ref)
pnpm dlx shadcn@latest registry validate acme/toolkit#v1.0.0

# Initialize the MCP server (--client: claude|cursor|vscode|codex|code)
pnpm dlx shadcn@latest mcp init --client claude
```

> This repo uses `bun`. Substitute `bunx shadcn@latest ...` (or
> `bun dlx shadcn@latest ...`) for the `pnpm dlx` forms above when running
> commands locally.
